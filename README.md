# 企业网站无障碍整改项目管理平台

面向审核员、开发人员、复测员和跨团队负责人的无障碍整改工作台。支持 WCAG 问题录入、同根因合并、复测流转、版本差异、批量分配、草稿恢复和整改报告导出。

## 技术栈

React + Ant Design + Zustand + React Router + TanStack Query + Axios + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62047`。

## 核心工作流

- 从站点、WCAG 条款、影响范围和证据链接建立问题台账。
- 将同根因问题合并为整改项，并批量指派团队、优先级和截止日期。
- 开发提交修复说明与复测环境，复测员逐项通过、退回或标记不适用。
- 保存常用筛选，比较版本差异，恢复未提交编辑并导出整改报告。

## 根因组与成员版本

同根因问题以**根因组（RootCauseGroup）**承载，组实体自带 `memberVersion`（成员版本，初始 v1）：

- **只改根因和状态、不动成员**不会升版本；成员集合每次增减（合并、整组并入、移出成员、解散）都令 `memberVersion +1`。
- 合并请求必须携带提交方读取到的每个相关组的期望版本（`expectedVersions`）。两名审核员同时合并同一条问题时，晚到方按服务端最新成员版本核对，过期即返回 409 `version-conflict` 并回传最新工作区，由对方重新确认后才能提交。
- **已通过保护**：已通过成员只能留在原根因组；已通过的独立问题只能作为目标主问题。任何会把“已通过”降级为成员或移到别组的合并都会被 422 `passed-protected` 拒绝，已通过结论不会被吞掉。
- 成员移出时恢复降级前状态（`prevStatus`）；成员不足 2 条时根因组解散。
- 总览、复测队列（组内成员的复测记录聚合到主问题条目）、版本差异基线和整改报告统一由 `src/api/stats.ts` 按**当前成员**派生，缓存以成员签名为键，成员一变旧统计立即失效重算。
- 旧数据按现有 `mergedKeys` 合并关系回填根因组与成员版本（MSW 启动时 `backfillGroups`；Zustand 持久化数据在 v1→v2 迁移时回填），不改动任何既有状态。

纯领域逻辑（`src/api/groups.ts`、`src/api/stats.ts`）不依赖 React/MSW，测试见 `npm test`。
